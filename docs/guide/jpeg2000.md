# JPEG2000 Support

`modern-pdf-lib` reads the header of JPEG2000 (JP2 / J2K) data but does not decode its pixels in this release. `decodeJpeg2000()`, and `decodeStream()` or `decodeImageStream()` on a `JPXDecode` stream, throw `UnsupportedFilterError` (code `unsupported-filter`, `filter` `'JPXDecode'`). Earlier releases returned pixels from a decoder that was not a conformant JPEG 2000 decoder, so those pixels could be wrong. `parseTileInfo()` reads the image size and tile grid from the header.

## Overview

JPEG2000 (ISO/IEC 15444 / ITU-T T.800) is commonly used in:

- **Medical imaging** (DICOM) — 16-bit grayscale, lossless compression
- **Satellite and geospatial** — large tiled images, multi-spectral bands
- **Government archives** — PDF/A-2 and PDF/A-3 allow JPEG2000 as a native image format
- **Digital cinema** (DCI) — 12-bit 4K/8K frames

PDF uses the **JPXDecode** filter to embed JPEG2000 images. A PDF that holds `JPXDecode` image streams still loads, saves, merges and copies: the streams are written back byte for byte, and `extractImages()` returns such images with their encoded bytes.

## What Throws

| Call | Result |
|:-----|:-------|
| `decodeJpeg2000()` | Throws `UnsupportedFilterError`; the data is not read |
| `decodeStream()`, `decodeImageStream()` with a `JPXDecode` filter | Throw `UnsupportedFilterError` |
| `decodeTile()`, `decodeTileRegion()`, `assembleTiles()` | Throw `UnsupportedFilterError`; they returned compressed tile data, not pixels, in earlier releases |
| `parseTileInfo()` | Reads the image size and tile grid from the header |
| `optimizeAllImages()` | Leaves a `JPXDecode` image unchanged and lists it as skipped |
| `extractPageImages()` | Leaves a `JPXDecode` image out; rendering draws no images in this release |

```ts
import { decodeJpeg2000, UnsupportedFilterError } from 'modern-pdf-lib';

try {
  decodeJpeg2000(j2kBytes);
} catch (err) {
  if (err instanceof UnsupportedFilterError) {
    console.log(err.code, err.filter); // 'unsupported-filter' 'JPXDecode'
  } else {
    throw err;
  }
}
```

## Reading Header Information

`parseTileInfo()` reads the SIZ marker, so it works without decoding:

```ts
import { parseTileInfo } from 'modern-pdf-lib';

const info = parseTileInfo(j2kBytes);
console.log(`Image: ${info.imageWidth}x${info.imageHeight}`);
console.log(`Tiles: ${info.tilesX}x${info.tilesY} (${info.tileWidth}x${info.tileHeight} each)`);
console.log(`${info.components} components, ${info.bitsPerComponent} bits`);
```

`getComponentDepths()` and `summarizeBitDepth()` read the per-component bit depth and signedness from the same marker:

```ts
import { getComponentDepths, summarizeBitDepth } from 'modern-pdf-lib';

const depths = getComponentDepths(j2kBytes);
const summary = summarizeBitDepth(depths);

console.log(`${summary.components} components, ${summary.bitsPerComponent}-bit`);
console.log(`Signed: ${summary.isSigned}`);
```

## Bit-Depth Helpers

Medical and scientific images often use 12-bit or 16-bit component depths. These helpers convert component data between depths. They work on bytes you already hold; the library does not produce JPEG2000 pixels in this release.

```ts
import {
  downscale16To8,
  upscale8To16,
  normalizeComponentDepth,
  offsetSignedToUnsigned,
} from 'modern-pdf-lib';

// 16-bit big-endian samples to 8-bit
const data8 = downscale16To8(samples16, 16);

// 8-bit samples to 16-bit
const data16 = upscale8To16(data8);

// Any depth to any depth (1-16 bits)
const data10to8 = normalizeComponentDepth(data10bit, 10, 8);

// Signed components to the unsigned range [0, 2^bits - 1]
const unsigned = offsetSignedToUnsigned(signedData, 12);
```

## Transcoding to JPEG

`optimizeAllImages()` does not transcode JPEG2000 images in this release: it lists each one as skipped, with the reason `Image filter JPXDecode is not decoded in this release` once the JPEG encoder is initialised (see [Image Optimization](./image-optimization.md)). The pixels of such an image have to come from a decoder outside the library.
